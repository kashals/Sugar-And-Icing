## 2025-02-14 - Fix IDOR in Account Deletion Endpoint
**Vulnerability:** Insecure Direct Object Reference (IDOR) and authentication bypass in `app/api/account/delete/route.ts`. The endpoint read the `userId` to delete directly from the request body (`const { userId } = await request.json();`) instead of reliably extracting it from the authenticated user token. A malicious user could potentially forge a request to delete another user's account if the flawed `userId` validation condition (`if (userError || !user || user.id !== userId)`) somehow permitted it or if they bypassed the `authHeader` block.
**Learning:** Security-critical actions (like account deletion, order mutation, etc.) must NEVER trust client-provided identifying information (e.g. `userId` in JSON body) when determining the subject of the action. Even if validation is present, it's safer and simpler to rely solely on the authenticated token.
**Prevention:** Always extract the `userId` from the verified server-side authentication context (e.g. `supabase.auth.getUser(token)`). Ensure authorization checks fail closed (deny by default).
